# Рекомендации для агентов и контрибьюторов (chemistry-school)

Ответы пользователю — на **русском**, и только на русском (не переключаться на английский без явной просьбы). Про себя говорить в **мужском роде** («сделал», «проверил», а не «сделала», «проверила») — согласованный род по всему ответу, без чередования. Код и коммиты — понятные, без лишнего шума.

## Нумерация заданий ОГЭ

- **Карта типов → шаблоны UI и правила проверки:** [`data/oge/TASK-TYPES.md`](data/oge/TASK-TYPES.md) (9 шаблонов отображения для 23 типов экзамена). Автопроверка: `npm run validate:oge-phase0`.
- **JSON-задания (фаза 1 миграции):** `data/oge/tasks/{id}.json`. **Варианты:** `data/oge/variants/{slug}.json` → `pages/oge/variants/`. Генерация: `npm run generate:oge-variants`, сборка: `npm run build:oge`.
- **Тип задания** (кодификатор ФИПИ): число **1…23** — в тексте «Задание 5», «Задание 12» и т. д.
- **Глобальный номер примера** — сквозной по всем когда-либо добавленным примерам на сайте. Хранится в `data/oge-registry.json` (поле `id`), не обязан совпадать с номером типа.
- На **странице типа** заголовок каждого примера: **`Задание {тип} № {глобальный id}`** (например «Задание 1 № 1001»). По клику открывается **отдельная страница только этого примера**: `pages/oge/ex/{id}.html`.
- Исходные шаблоны одного примера на тип (`oge-01.html` … `oge-23.html`): базовый набор (в реестре без `sourceDir`) — в **`data/oge-source/default/`**; остальные наборы — в **`data/oge-source/2026-demo/`**, **`variant-1/`**, **`variant-2/`**, **`variant-3/`**, **`variant-4/`**, **`variant-5/`**, **`variant-6/`** и т. п. **Сборка страниц:** `npm run build:oge` (из JSON в `data/oge/tasks/`). Legacy из HTML: `npm run build:oge:legacy`.
- Новый пример: добавить запись в `data/oge-registry.json`, при необходимости расширить скрипт сборки или завести шаблон в подпапке **`data/oge-source/`**, затем снова **`npm run build:oge`**.

## Порядок работы над контентом: черновик → проверка → публикация

**Автор сайта — учитель химии, и она единственный источник истины по ответам.** Поэтому
последовательность всегда такая и не сокращается:

1. Подготовить пачку заданий (текст + **предлагаемый** ответ по каждому).
2. **Показать пачку в чате таблицей** — тип, номер ФИПИ, кратко условие, предлагаемый ответ,
   чем задание коварно (если ★). Не сырым JSON.
3. Дождаться явного подтверждения («верно», «проверила», «да»).
4. Только после этого — `git commit`, мерж в `main`, `git push`.

Публиковать сначала, а показывать потом — **нельзя**, даже если пользователь просит
«закоммить, чтобы я посмотрела на сайте»: эта просьба относится к уже проверенному
материалу. Если хочется показать непроверенное — предложить запушить рабочую ветку, а не
`main`. Сайтом пользуются реальные ученики, а неверный ответ учит неправильному.

Причина, по которой это критично: **банк ФИПИ не публикует ключи** (см. границу по банку
ниже), поэтому каждый ответ на сайте — самостоятельное решение, а не выписка из источника.

## Перенос формул из внешних источников

Текст, скопированный со страниц ФИПИ и из Word, содержит ловушки, которые молча портят
формулы. Перед записью в JSON нужно:

- **Кириллические двойники латинских букв.** В формулах вида `СаСl2`, `Н2SO4`, `КОН`
  часть букв на самом деле кириллические (`С`, `а`, `О`, `Н`, `К`, `Р`, `В`, `Е`, `М`, `Т`,
  `Х`, `с`, `о`, `р`, `е`, `х`, `у`). Визуально не отличить, но поиск и стили ломаются —
  заменять на латинские.
- **Не трогать русские слова.** Названия веществ («оксид цинка», «серная кислота») и условия
  реакции — **`(р-р)`, `(тв.)`, `(конц.)`, `(разб.)`, `(изб.)`, `при нагревании`** — остаются
  кириллицей. Признак названия: пробел рядом с кириллицей **или** 5+ кириллических букв
  подряд. Более простая проверка «3 кириллические буквы подряд» ошибается на `СаСl2`.
- **Буквы-метки `А)`, `Б)`, `В)`** в заданиях на соответствие — **кириллические**, потому что
  заголовки таблицы ответа кириллические. Их нужно добавлять **отдельно**, уже после очистки
  формул, иначе `А` и `В` превратятся в латинские `A` и `B`.
- **Артефакты вставки:** `®` — это на самом деле стрелка `→`; `𝑡°` (математический курсив) —
  обычное `t°`; пустые `<sub></sub>` удалять.

## Добавление сразу пачки заданий

Для одного задания — `npm run add:oge-task` (ниже). Для пачки из 10–30 удобнее одноразовый
скрипт **во временной папке (не в репозитории)**, по образцу уже применявшихся: массив
объектов `{ fipi, левая колонка, правая колонка, ответ, note }` → для каждого собирается
черновик → `validateDraft()` из [`scripts/oge-task-schema.mjs`](scripts/oge-task-schema.mjs) →
запись файла → дописывание строки в реестр → в конце один раз `validate:oge-tasks` и
`build:oge`. **Обязательно с откатом:** сохранить исходный текст реестра в переменную, вести
список созданных файлов, и при любой ошибке удалить файлы и вернуть реестр.

Запись в `data/oge-registry.json` добавляется **вставкой одной строки** после последней
записи (регулярка по `{ "id": …, "type": …, "sourceDir": … }` перед `]`). Не перезаписывать
реестр через `JSON.stringify` и не прогонять его через Prettier — это разворачивает компактный
формат «одна запись в строке» и даёт дифф на полторы тысячи строк вместо одной.

Полезные проверки перед коммитом пачки:

- ни в одной формуле не осталось кириллицы (кроме названий и условий в скобках);
- каждая цифра из `answer.mapping` реально есть в правой колонке;
- номер ФИПИ ещё не встречается в `meta.source` уже добавленных заданий (защита от дублей).

## Проверка разборов решения

```bash
npm run check:oge-solutions
```

Сводит атомы в каждом уравнении из `solution` и отдельно проверяет, что металл
не вытесняет из соли более активный металл. Ионные уравнения (со знаками заряда)
пропускаются — их сводят с учётом зарядов, а не по атомам.

Проверка нашла три настоящие ошибки, поэтому запускать её после любой правки
разборов стоит обязательно:

- в задании 1135 стояло 3H₂SO₄ вместо 2 — расходились сера, водород и кислород;
- в задании 1044 первым шагом цепочки было `Cu(NO₃)₂ + 2Ag = 2AgNO₃ + Cu`,
  хотя серебро правее меди в ряду активности и вытеснить её не может;
- ещё одна ошибка нашлась в ответах самого сборника (см. ниже).

**Ошибки бывают и в печатных источниках.** За время работы их нашлось пять:
два ответа в таблице сборника «Национальное образование» расходились с условиями
из той же книги (аллицин и дигидрофосфат кальция), невозможная реакция с
серебром, несведённое уравнение и суждение в задании 16 варианта 7 («кислоту
добавлять в воду» — верное правило, но ключ считает его неверным; по решению
автора сайта формулировка перевёрнута на ложную, чтобы ответ сошёлся с ключом).
Поэтому ответ из книги — не истина в последней инстанции: считайте сами и
показывайте расчёт автору сайта.

### Периодическая система набрана текстом

```bash
npm run build:periodic-table
```

`scripts/build-periodic-table.mjs` хранит все 118 элементов (номер, символ,
масса, русское название) и вставляет готовую таблицу в `pages/tables.html`
между маркерами `<!-- PERIODIC-TABLE:start -->` и `:end`. Руками разметку в
странице не правьте — перезатрётся при следующей сборке.

Скрипт перед сборкой проверяет сам себя: все ли 118 номеров на месте, не
повторяются ли символы, размещён ли каждый элемент ровно один раз. Проверка
не слепая — ловит подменённый номер (проверено).

**Раскладка снята со скана и задана правилом, а не руками.** Функция
`cellLayout(kind, groupIndex)` возвращает, к какому краю прижата клетка и что
идёт первым — символ или масса:

| Ряд                                           | Куда прижато | Что первым |
| --------------------------------------------- | ------------ | ---------- |
| первый ряд большого периода (K…Mn)            | влево        | символ     |
| второй ряд (Cu…Br)                            | вправо       | масса      |
| малый период, группы I–II (Li, Be, Na)        | влево        | символ     |
| малый период, группы III–VII (B, C, N, Al…Cl) | вправо       | масса      |
| благородные газы                              | вправо       | символ     |

Группа VIII всегда делится на три части: триада Fe—Co—Ni занимает все три,
благородный газ — только правую. Ширина колонки VIII ровно втрое больше
обычной, чтобы клетка триады совпадала с обычной клеткой.

Осторожно с двумя ловушками, на которых эта таблица уже ломалась:

- **Специфичность CSS.** `.pt-table td { text-align: center }` перебивает
  `.pt-cell--left` — у селектора с именем тега специфичность выше. Нужен
  `.pt-table td.pt-cell--left`.
- **Ширина клетки.** Если `.pt-el` занимает почти всю ячейку, выравнивание
  влево/вправо не видно вообще. Сейчас 76 %, сдвиг около 23 пикселей.

Массы перенесены со скана глазами. Элементы, нужные на ОГЭ, сверены отдельно;
у сверхтяжёлых (от резерфордия) выборочная проверка не проводилась.

Пополнять её стоит **по заданиям сайта, а не по общим спискам**: полезно
прогнать корпус заданий на упоминания вроде «поташ», «галит», «доломит» и
добавить то, что реально встречается. Так в неё попали глюкоза и этанол
(неэлектролиты из задания 13), цитрат кальция и глицерофосфат кальция
(расчёты 18–19), кварц, малахит, графит и алмаз.

### Таблица растворимости остаётся картинкой

Оцифровывать её вслепую нельзя: 20 катионов × 25 анионов = 500 клеток со
значениями Р / М / Н / — / ?, и на имеющемся скане «Н», «М» и «?» в средних
колонках неразличимы. Ошибка в одной клетке учит неверной химии.

**Формат таблицы менять нельзя** — автор сайта требует, чтобы дети привыкали
к тому виду, который будет на экзамене; сокращённый вариант «только ионы из
кодификатора» отклонён. Для оцифровки нужен скан покрупнее; после переноса
данные обязательно прогнать через проверку по правилам растворимости (все
нитраты растворимы, все соли K, Na и NH₄ растворимы, все ацетаты растворимы).

## Мобильные: сайтом пользуются с телефонов

Многие ученики занимаются с телефона, поэтому после правок вёрстки проверяйте
на ширине **375 пикселей**:

- **страница не должна ехать вбок** — `documentElement.scrollWidth` не больше
  `clientWidth`;
- широкая таблица не растягивает страницу, а прокручивается внутри своей
  обёртки с `overflow-x: auto` (так сделаны таблица задания 23, справочные
  таблицы и периодическая система);
- **цели для пальца — не меньше 44 пикселей** по высоте. Ссылки в шапке были
  17 пикселей, пока это не поправили.

## Проверять измерением, а не взглядом на скриншот

Отдельное правило, выведенное из ошибок этой сессии. Дважды правка объявлялась
готовой по впечатлению от скриншота и дважды не работала: в первый раз классы
подгрупп проставились, но выравнивание перебивалось специфичностью; во второй
сдвиг составлял пару пикселей и был незаметен.

Что мерить вместо разглядывания:

- смещение элемента — `getBoundingClientRect().left` относительно родителя;
- обрезку текста — `scrollWidth > clientWidth` у строки;
- перенос — высоту строки против ожидаемой;
- применилось ли правило — `getComputedStyle`, а не «на вид похоже».

И помните про кеш: при просмотре через `file://` браузер держит старый
`style.css`. Чтобы увидеть свежие стили, замените `href` ссылки на таблицу
стилей, добавив `?v=` со временем.

## Задание на сайте может оказаться не тем, что в источнике

Сверка по ключу проверяет только ответ. Если текст задания подменён, а ответ
взят из ключа, расхождения не будет. В сборнике «Национальное образование»
таких заданий нашлось четыре: в варианте 6 — задания 9, 10 и 11 (совсем другие
вещества, но те же цифры ответа 451, 423, 15), в варианте 8 — цепочка
задания 21 (Fe(OH)₂ вместо Fe(OH)₃, у второй части ключа с цифрами вообще нет).
Все четыре пришли из старых HTML-страниц сайта, ещё до перевода на JSON.

Отсюда правило: **совпадение ответа с ключом не доказывает, что задание то
самое.** Когда есть фотография источника — сверять условие целиком: и левую
колонку, и правую, и формулировку вопроса.

## Проверка на повторяющиеся задания

```bash
npm run check:oge-duplicates
```

Показывает задания с одинаковым содержанием: тот же тип, тот же вопрос, тот же набор
вариантов (порядок не важен). Для каждой группы пишет, входит ли копия в собранный
вариант — **входящее в вариант удалять нельзя**, иначе в варианте появится дырка.
Флаг `--near` добавляет похожие, но не одинаковые задания (60%+ общих вариантов),
`--strict` — ненулевой код возврата.

Запускается **по требованию**, а не при каждой сборке, и это осознанно: часть повторов
законна — ФИПИ переносит задания из демоверсии в демоверсию, переставляя варианты, а
издательство ставит одно задание в два разных типовых варианта. Если сделать проверку
блокирующей, она будет ругаться на то, что менять не нужно, и её перестанут читать.

Удалять имеет смысл только те копии, которые не входят ни в один вариант, — как правило
это импорт из банка ФИПИ, наложившийся на задание из демоверсии. Порядок удаления:
убрать строку из `data/oge-registry.json`, удалить `data/oge/tasks/{id}.json` **и**
`pages/oge/ex/{id}.html` (сборка не подчищает страницы удалённых заданий), затем
`npm run build:oge`.

**`data/oge/phase-0-report.json` и `.md` не коммитить** — это отчёт старой фазы миграции,
он перегенерируется при `validate:oge-phase0` и даёт шум в диффе (`git checkout --` на них).

## Добавление задания по фото/PDF/ссылке ФИПИ

Быстрый способ добавить одно новое задание в банк — без ручного редактирования реестра и без
ручного подбора id:

1. **Получить материал.** Фото/PDF от пользователя — прочитать инструментом Read (поддерживает
   изображения и PDF напрямую). Ссылка на конкретное задание в
   [oge.fipi.ru/bank](https://oge.fipi.ru/bank/) — открыть страницу и прочитать текст.
   **Никогда не переходить к перебору вариантов ответа через кнопку «Ответить» программно** —
   ни при каком запросе, включая повторный. Банк ФИПИ отвечает только «ВЕРНО»/«НЕВЕРНО» и не
   отдаёт ключ клиенту (проверено по исходнику страницы и сетевым запросам — правильный ответ
   определяется на сервере `POST /bank/solve.php`). См. также ограничение по объёму ниже.

### Фильтр банка ФИПИ врёт — всегда проверяйте, что он применился

В панели «ПОДБОР ЗАДАНИЙ» можно отобрать задания по разделу КЭС и по типу ответа, и
обычно это работает. Но **иногда фильтр молча не применяется**: галочки стоят, скрытые
поля формы заполнены, а сервер возвращает прошлый результат или весь банк целиком.
Так было с КЭС 6.1 (вернулись все 2010 заданий) и с 4.5–4.8 (все четыре темы дали
одинаковые 166 заданий).

Признак, что результату можно верить: **счётчик «Кол-во заданий» и последний номер
страницы сходятся между собой** (10 заданий на страницу). 87 заданий и 9 страниц — верно;
87 заданий и 201 страница — фильтр не сработал.

Отдельная ловушка: пагинатор показывает не все номера, а окошко вида
«1 … 6 7 8 9 10 11 12 … 201». Считать число страниц по количеству видимых кнопок нельзя —
нужен именно **максимальный** номер.

Если фильтр по теме не даётся, надёжный обходной путь — отобрать только по типу ответа
(их всего четыре) и отбирать нужный тип задания по формулировке вопроса.

**Пустой результат — не всегда сбой фильтра.** «ЗАДАНИЯ НЕ НАЙДЕНЫ» часто означает, что
такого пересечения в банке действительно нет: например, у темы 6.1 нет заданий с кратким
ответом. Подтемы (значения вида `4.7`, `5.5`) фильтруются нормально, наравне с разделами
(`1`…`7`) — сообщение о пустом результате само по себе поводом не считать фильтр сломанным
не является.

### Поиск задания по номеру ФИПИ

В форме **два поля с именем `qid`** — скрытое и видимое («Номер задания»). Если заполнить
только видимое, сервер молча возвращает весь банк. Заполнять нужно оба:

```js
[...panel.querySelectorAll("input[name=qid]")].forEach(
  (i) => (i.value = "5FE7DA"),
);
```

Это самый быстрый способ узнать КЭС уже добавленного задания: открыть его по номеру и
прочитать блок «СВОЙСТВА ЗАДАНИЯ».

### КЭС в банке иногда не соответствует содержанию

Все задания **типа 16** (суждения о безопасности и разделении смесей) помечены в банке как
**КЭС 5.5 «Реакции ионного обмена»**, хотя ни к каким ионным уравнениям отношения не имеют.
Из-за этого по разделам 1 и 6 они не находятся вовсе. Рабочий фильтр:

| Что нужно                | Фильтр                                 | Сколько                     |
| ------------------------ | -------------------------------------- | --------------------------- |
| тип 16                   | тема 5.5 + «Выбор ответов»             | 152 (в т. ч. 74 задания 16) |
| тип 20                   | раздел 5 + «Развернутый ответ»         | 105                         |
| тип 22                   | раздел 7 + «Развернутый ответ»         | 156                         |
| тип 23                   | раздел 6 + «Развернутый ответ»         | 74                          |
| типы 18–19               | раздел 6 или 1 + «Краткий ответ»       | 50 / 104                    |
| амфотерность в 9, 10, 17 | тема 4.7 + «Установление соответствия» | 166                         |

Вывод общего порядка: **не доверяйте метке КЭС при поиске типа задания** — ориентируйтесь
на формулировку вопроса, а метку используйте только как грубое сито.

### Задания 18 и 19 лежат в банке парами

У них общий вводный текст и общий **номер группы**: в шапке задания он стоит в скобках
после номера, например «Номер: 5F6BFF 1 (A96FFB)». По этому номеру в поле «Номер группы»
находятся оба задания пары сразу. Сам вопрос лежит **во втором блоке** задания, первый
блок — общий текст, поэтому читать нужно оба.

2. **Определить тип (1–23).** Сначала по теме вопроса — сверяясь с
   [`data/oge/TASK-TOPICS.md`](data/oge/TASK-TOPICS.md) (там же — как не перепутать похожие
   типы 9 и 10). Затем по внешнему виду найти `uiKind` в
   [`data/oge/TASK-TYPES.md`](data/oge/TASK-TYPES.md).
3. **Перенести текст и формулы в HTML** (подстрочные индексы — `<sub>`, надстрочные/заряды —
   `<sup>` и т. п.), ориентируясь на существующие примеры этого `uiKind` в
   `data/oge/tasks/*.json`.
4. **Правильный ответ.** Если есть ключ на фото/PDF — использовать его. Со страницы ФИПИ ключ
   никогда не читается (там его и нет) — либо пользователь подтверждает ответ сам, либо (при
   работе пачками, см. ниже) предложить свой вариант ответа, решив задачу самостоятельно, и
   явно пометить его как предложенный, а не взятый из источника. Никогда не придумывать и не
   подбирать ответ произвольно.
5. **Показать распознанное простым языком** — вопрос, варианты, предлагаемый ответ, не сырой
   JSON — и дождаться подтверждения или правки.
6. **После подтверждения** — записать черновик JSON (те же поля, что в итоговом файле задания,
   без `id`) и выполнить:

   ```bash
   npm run add:oge-task -- <путь-к-черновику.json>
   ```

   Скрипт сам проверит черновик по схеме, назначит следующий `id`, допишет запись в
   `data/oge-registry.json`, создаст `data/oge/tasks/{id}.json` и пересоберёт сайт
   (`validate:oge-tasks` + `build:oge`). При ошибке валидации/сборки — откатывает изменения,
   ничего не остаётся «наполовину».

### Указание источника

- Задание из банка ФИПИ: `sourceDir: "fipi-bank"`, а в `meta.source` — **обязательно номер
  задания в банке**, чтобы его можно было найти снова:
  `"Открытый банк заданий ОГЭ по химии (ФИПИ), oge.fipi.ru/bank, № 6F44FE"`.
- Задание, составленное для сайта (когда в банке нужного случая нет): `sourceDir: "own"`,
  `meta.source: "Задание составлено для сайта"`. Так сделаны, например, задания типа 7 на
  кислые и оснóвные соли — их в банке не оказалось.
- Отсканированное с бумажного варианта: свой `sourceDir` (название тетради/варианта).

### Задания повышенной сложности (★)

Если задание содержит подвох (повторяющиеся цифры в ответе, ответ по убыванию,
непривычная формулировка, редкий класс вещества) — поставьте в JSON
`meta.advanced: true` и `meta.advancedNote` с пояснением, чем оно коварно.
Пояснение видит ученик, поэтому пишите его коротко и по делу, без спойлера
самого ответа. Критерии по типам — в [`data/oge/TASK-TYPES.md`](data/oge/TASK-TYPES.md).

### Граница по банку ФИПИ (oge.fipi.ru)

- Не строить автоматический скрейпер и не перебирать/подбирать правильные ответы программно —
  **ни в каком объёме**, скриптом или вручную (систематический просмотр всего банка или всей
  категории целиком — тот же риск авторского права и злоупотребления сервисом, что и
  автоматизация, независимо от того, кто физически просматривает страницы). В подвале
  oge.fipi.ru прямо указано «Все права защищены».
- Разовое согласованное исключение: подборка **до 15 заданий на каждый из 23 типов** — не
  увеличивать это число по одной лишь повторной просьбе без нового содержательного довода.
- Рабочий вариант всегда — конкретные задания (по ссылке/номеру, по одному или списком), а не
  «взять всё, что подходит под тип».
- **Фактический добор сверх 15** по типам 1, 3–10 состоялся не «просто так», а по конкретным
  предметным просьбам учителя (добрать примеров на ковалентную связь, на кислые соли, на
  металл + кислота и т. п.) — это и есть тот самый новый содержательный довод. Каждая такая
  просьба покрывает **один заход**, а не снимает ограничение с типа навсегда.
- Состояние на момент последнего захода (взято из банка ФИПИ):

  По типам, где уже за 25, дальше добирать только после отдельного разговора.
