# Карта типов ОГЭ: examType → uiKind

Справочник для разработки и наполнения контента.

- **examType** — номер задания в экзамене (1–23), кодификатор ФИПИ.
- **uiKind** — шаблон отображения и проверки на сайте (их **9**, не 23).

Полная карта типов, шаблонов UI и правил автопроверки.

**Проверка карты (фаза 0 миграции):** `npm run validate:oge-phase0` → [`phase-0-report.md`](phase-0-report.md). Подробнее — [`MIGRATION.md`](MIGRATION.md).

Чтобы определить номер типа **по содержанию вопроса** (а не по внешнему виду) — см. [`TASK-TOPICS.md`](TASK-TOPICS.md).

## Пометка «повышенная сложность» (★)

Любому заданию можно поставить `meta.advanced: true` и обязательное к нему
`meta.advancedNote` — короткое пояснение, **чем именно** задание коварнее обычного.
Тогда рядом с заголовком появляется ★, а под ним — подсказка с этим пояснением.
Пометка также попадает в `pages/oge/task-index.json`, и в конструкторе вариантов
можно собрать набор только из таких заданий.

Что имеет смысл помечать:

- **тип 4** — когда две буквы дают одну и ту же цифру (ответы вида 113, 442),
  когда спрашивают валентность вместо степени окисления, когда в перечне гидриды,
  карбиды, силициды, фосфиды (Ba<sub>2</sub>H, CaC<sub>2</sub>, Mg<sub>2</sub>Si, PH<sub>4</sub>I);
- **тип 3** — когда цифры в ответе идут по убыванию (3-2-1), когда элементы взяты
  из разных периодов *и* групп сразу;
- **тип 5** — вещества сразу с двумя типами связи, а также ионные вещества, внутри
  которых есть ковалентная связь (KOH, NH<sub>4</sub>F);
- **тип 6** — формулировка «верно для одного и неверно для другого»;
- **тип 7** — кислые и оснóвные соли, OF<sub>2</sub> среди «оксидов», несолеобразующие оксиды.

## Правила автопроверки подробнее

### `twoChoice` (типы 1, 5, 6, 8, 11, 13, 14)

- Выбрать **ровно 2** утверждения из списка (5 или 6 пунктов — параметр задания).
- Порядок номеров не важен.
- Засчитываются галочки, ячейки или оба способа при согласованном наборе цифр.

### `matchTriple` (типы 4, 9, 10, 12, 15, 17)

- Три буквы (А, Б, В) сопоставляются цифрам из правой колонки.
- Число вариантов справа (2–5) — параметр задания, шаблон один.

### `orderedDigits` (типы 3, 7)

- Ученик записывает цифры в ячейки **в заданном порядке** (порядок элементов или «сначала X, затем Y»).

#### Тип 3 допускает два шаблона

Формулировка задания 3 со временем менялась, поэтому для него разрешены **оба** шаблона:

- **`orderedDigits`** — нынешняя формулировка «Расположите химические элементы в порядке…»;
- **`twoChoice`** — прежняя формулировка «Выберите два верных продолжения… В ряду химических элементов X → Y → Z увеличивается…».

#### Тип 7 тоже допускает два шаблона

Здесь дело не в годе, а в самой постановке вопроса:

- **`orderedDigits`** — «выберите **соль и кислотный оксид**… запишите **сначала** номер соли,
  **затем** номер оксида»: вещества разных классов, порядок цифр важен;
- **`twoChoice`** — «выберите **два оснóвных оксида**… запишите номера выбранных ответов»:
  вещества одного класса, порядок любой.

Ставить `orderedDigits` на задание «два X» нельзя — тогда верный ответ в другом порядке
засчитался бы как ошибка.

#### Как это устроено

Список исключений задаётся в `ALSO_ALLOWED_UI_KINDS` (`scripts/oge-ui-kind-map.mjs`); проверка
шаблона идёт через `isAllowedUiKind()`. На страницах `type-03.html` и `type-07.html` примеры
обоих видов соседствуют и проверяются каждый по своим правилам.

### `multiChoiceFour` (тип 16)

- Всегда 4 суждения с чекбоксами и **4** ячейки ответа.
- В ключе может быть **1, 2, 3 или 4** верных номера — длина массива `correct` определяет это для конкретного задания.
- Ограничение «не больше N галочек» **не** ставить.

Пример JSON:

```json
"answer": { "correct": ["2", "3", "4"] }
```

### `numericInt` и `numericMassTable` (типы 18, 19)

- Эталон хранится как число уже в нужной точности (`16`, `1.6`, `8.48` и т. д.).
- Проверка: `parseFloat(ввод) === value` — **без** `Math.round`, `Math.abs` и допусков.
- Замена «.» на «,» в поле — через `OGE_answerDotsToCommasInField`, как сейчас.

### `openReference`, `experimentOpen` (типы 20–23)

- Кнопки «Проверить» нет; разбор в блоке `solution`.

## Связанные задания 18 и 19

В одном варианте ОГЭ задания 18 и 19 часто используют общий контекст (одно вещество). При хранении в JSON можно связать их полем `meta.linkedTaskId`.
